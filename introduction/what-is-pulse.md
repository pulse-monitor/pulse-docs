# Pulse 是什么？

Pulse 是一个轻量、自托管的基础设施可视化平台。

它把分散在各台服务器上的状态收拢到一个视图里：健康状况、 CPU / 内存 / 磁盘、
网络流量与连接、延迟与丢包、流量额度、成本与到期时间、以及需要你注意时的告警。

## 它解决什么问题

服务器从几台长到几十台之后，靠 SSH 挨个登进去看就不成立了。
问题不在于「有没有监控」，而在于回答这几个问题要花多久：

- 哪台正在异常？
- 哪些资源在持续升高？
- 哪条线路延迟或丢包不对劲？
- 哪台流量快到额度了？
- 哪台快到期了？

Pulse 让这些答案在一页里。

## 四类核心信号

| | 回答的问题 |
|---|---|
| **Health** | 服务器现在正不正常 |
| **Network** | 网络稳不稳，延迟和丢包有没有异常 |
| **Traffic** | 流量用了多少，还剩多少额度 |
| **Cost** | 这台多少钱，什么时候续费或到期 |

## 自托管

Server 部署在你自己的基础设施里，数据不经过第三方 SaaS。

唯一的外部请求是两处，都可以关掉或换源：汇率（用于多币种折算）和 GeoIP 数据库
（用于按 IP 判断国家，**库在本地， IP 不外传**）。

## 边界

Pulse 专注于 **Visibility**，而不是 **Control**。

Agent 的职责只有两个：**采集**、**上报**。它不开放入站端口、不提供远程 Shell、
不执行来自 Server 的命令。

这不是一句口号 —— 协议里根本没有「执行」这类消息， CI 里有断言逐条盯着。
详见[安全概览](/security/)。

## 规模

设计目标是 **50 ～ 200 台**。

单个静态二进制 + SQLite，不需要额外的数据库运维。数据分层上卷
（原始 → 分钟 → 小时 → 天），查询按时间跨度自动选层，所以库不会随时间线性膨胀。

## 不做什么

- **不做远程运维**。没有 Shell、没有命令下发、没有文件操作。
- **不用 0 填充采不到的指标**。采不到就如实标记为不可用，前端隐藏那一行。
  一个写着「温度 0°C」的面板比没有这一项更糟 —— 它让你以为自己知道。
